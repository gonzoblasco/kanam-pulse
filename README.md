# Kanam Pulse

[![Status](https://img.shields.io/badge/status-pre--release-yellow)](https://github.com/gonzoblasco/kanam-pulse)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Kanam Pulse is a **local-first macOS health monitor and cleaner**: a web dashboard that reads the real pulse of your machine (disk, memory, CPU, security, network), scores it 0-100, explains the audit in plain language through a **local** AI model, and helps you act on it with explicit, granular consent.

No telemetry. No accounts. No data leaves your machine.

## What it is

A local web app: a small Fastify server binds to `127.0.0.1` only, runs the health-check engine, and serves a read-only React dashboard. The dashboard shows a weighted health score, live memory/load metrics, the fixable caches and heavy processes found on your machine, and - when you ask for it - a plain-language summary of the audit generated by your own local Ollama instance.

The engine (`@kanam-pulse/core`) is inherited from a validated terminal health-check implementation (`system-health-check` v1.0.0), so the checks and fix planners shipped in this repo have been exercised on real machines before they reached the web UI.

## Features

- **Health checks** (`packages/core`): disk, memory (real `vm_stat` anonymous-minus-purgeable, like Activity Monitor), CPU, security, and network. Each check scores 0-100; the overall score is weighted (disk 25%, memory 25%, CPU 20%, security 15%, network 15%) and mapped to `healthy` / `attention` / `degraded` from the worst check.
- **Read-only dashboard** (`packages/web`, Vite + React + TypeScript) that consumes `GET /api/run` and renders the score, per-check status, and the fixes panel. No dashboard route mutates anything by itself.
- **Consent-driven fixes**: `GET /api/fixes/scan` lists safe, regenerable cache targets and heavy processes. A **dry-run** (`POST /api/fixes/dry-run`) estimates what would be freed or killed without executing anything. Applying (`POST /api/fixes/apply`) requires explicit per-target selection and an accessible confirmation dialog, and the server refuses the request unless it carries `confirmed: true`.
  - The scan covers only well-known cache locations (app caches, developer caches, npm/yarn caches) and never user data.
  - Cleanup is **trash-style**: each cache entry is moved to the macOS Trash via `/usr/bin/trash`, never permanently deleted. If the Trash is unavailable, the cleaner refuses to run instead of falling back to a destructive delete.
  - Heavy processes are killable only below a strict protected list (`kernel_task`, `launchd`, `WindowServer`, `loginwindow`, `mds`, `systemd`, `init`, ...) and diagnostic commands the engine itself spawns are never listed.
- **Local AI audit summary**: the "Explain this audit" button sends only aggregate metrics (scores, statuses, sanitized suggestion text - never paths or file contents) to a local Ollama instance. The prompt is deliberately summary-only. If Ollama is not running, the button stays but reports a short notice; the audit flow never depends on this feature.
- **Live metrics over SSE**: `GET /api/metrics/stream` pushes memory (bytes) and 1-minute load average every 2 seconds.
- **i18n-ready UI**: all user-facing strings are centralized in `packages/web/src/i18n/strings.ts` with **Spanish as the default locale** (SPEC decision) and a complete English pack. Switch with `localStorage['locale'] = 'en' | 'es'`.

## Architecture

```
kanam-pulse/
├── packages/
│   ├── core/          # Health-check engine: checks, runner, history, fix planners
│   │   └── src/       #   Plain ESM JavaScript + JSDoc (zero runtime deps)
│   │       ├── checks/    # disk, memory, cpu, security, network
│   │       ├── core/      # runner (weighted score), reporter, history, exec
│   │       ├── fix/       # cleaner.js (safe caches), processes.js (protected list)
│   │       └── audit/     # summary.js (Ollama prompt, privacy-sanitized)
│   ├── server/        # Fastify API + SSE stream (TypeScript)
│   │   └── src/       #   app.js (routes) + index.js (binds 127.0.0.1)
│   └── web/           # Dashboard: Vite + React 18 + TypeScript
│       └── src/       #   components/, hooks/, i18n/, styles/
├── docs/
│   └── SPEC-v1.md     # v1 scope, principles, open questions
└── .github/workflows/ # CI: test + build on Node 20 (GitHub Actions)
```

- **`@kanam-pulse/core`** - the engine. Zero runtime dependencies, pure ESM. Each check is isolated: one failing check never takes down the battery. Ported with its full test suite from the validated CLI implementation.
- **`@kanam-pulse/server`** - thin Fastify wrapper over the engine. Binds `127.0.0.1` only (`PORT` env to override). Serves the REST surface and the SSE metrics stream.
- **`kanam-pulse-web`** - the dashboard. Fetches `/api/run`, renders score + status, drives the consent flow (scan -> select -> dry-run -> confirm dialog -> apply), and offers the optional Ollama explanation.

### API (server)

| Method | Route | Description |
|---|---|---|
| GET | `/api/health` | Server version (`{ ok, version }`) |
| GET | `/api/checks` | Available check ids + names |
| GET | `/api/run?checks=disk,memory,cpu,security,network` | Full battery: weighted score, status, per-check results, run info |
| GET | `/api/history` | Past run summaries (persisted locally in `~/.system-health-check/history.json`, max 100 entries) |
| POST | `/api/audit/explain` | Optional local AI summary; `{ available: false }` when Ollama is down |
| GET | `/api/fixes/scan` | Safe cache targets + heavy processes (read-only) |
| POST | `/api/fixes/dry-run` | Estimate for given targets - never executes anything |
| POST | `/api/fixes/apply` | Destructive actions; **requires** `confirmed: true` |
| GET | `/api/metrics/stream` | SSE: memory bytes + 1-min load every 2s |

## Quick start

Requirements: **Node.js >= 20** (workspaces engine floor) and npm. **Ollama is optional** - it is only needed for "Explain this audit".

```bash
# 1. Install + build all workspaces (core is plain ESM, server builds with tsc, web with vite)
npm ci
npm run build --workspaces --if-present

# 2. Terminal A - start the local API (binds 127.0.0.1:4270)
npm run start --workspace @kanam-pulse/server

# 3. Terminal B - start the dashboard dev server (Vite, default http://localhost:5173,
#    proxies /api -> http://localhost:4270 per vite.config.js)
npm run dev --workspace kanam-pulse-web
```

Open http://localhost:5173, run a scan, and try the flow. To confirm the API alone: `curl http://127.0.0.1:4270/api/health` and `curl "http://127.0.0.1:4270/api/run?checks=disk,memory,cpu,security,network"`.

> Linux note: checks degrade gracefully - macOS-specific pieces (e.g. `vm_stat` metrics) return `null` instead of failing the run.

## Consent & privacy principles

1. **Granular consent**: destructive actions are opt-in per target. Nothing is cleaned or killed without explicit selection plus an explicit confirmation, and the server enforces `confirmed: true` on `/api/fixes/apply`.
2. **Dry-run first**: applying stays disabled until a dry-run has produced an estimate. The dry-run endpoint never executes a cleanup or kill.
3. **Only regenerable caches, trash-style removal**: the cleaner touches well-known cache locations (app/developer/npm/yarn caches) whose contents are re-downloadable, and never user data, documents, or anything ambiguous. Every removed entry goes to the macOS Trash (via `/usr/bin/trash`) instead of being permanently deleted; if trash-style removal is unavailable, the cleaner refuses to run. Per the SPEC: destructive operations never use immediate permanent delete where trash-style is available.
4. **Protected processes are untouchable**: a strict blacklist (`kernel_task`, `launchd`, `WindowServer`, `mds`, ...) plus diagnostic commands the tool itself spawns are never selectable or killable.
5. **Zero telemetry**: no analytics, no crash reporting, no network calls beyond your own `127.0.0.1` API - and, when enabled, your own local Ollama. The AI prompt contains only aggregate scores and sanitized suggestion text, never paths or personal data.

## Accessibility

WCAG 2.2 AA is the baseline, not a checkbox:

- **Accessible confirmation dialogs**: `role="dialog"` + `aria-modal`, labelled and described, full focus trap (Tab cycles, Escape closes, focus restored to the opener).
- **ARIA live regions**: `role="status"` + `aria-live="polite"` announce dry-run estimates, apply results, and audit explanations; `role="alert"` surfaces errors.
- **Keyboard-first flows**: every action (scan, dry-run, apply, explain) is a focusable button with an accessible name; target checkboxes are properly `<label>`-associated.
- **Automated axe-core checks**: the a11y test suite (`accessibility.test.tsx`, 10 tests) runs axe against all three surfaces - the build fails on any critical/serious violation. Color-contrast is verified in the browser during manual audits (jsdom cannot compute layout).
